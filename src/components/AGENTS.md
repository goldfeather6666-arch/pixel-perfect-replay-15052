# Presentation rules
- Chat presentation uses AI Elements around Forge’s existing NDJSON transport and persisted messages; shared semantic tokens style workspace screens. Why: consistent controls without changing execution or history.
- PromptAssistance shows local hints while typing and explicit-request streamed BYOK refinement; proposals never replace changed drafts or execute tools. Why: useful drafting without hidden charges or consent changes.
- AppearanceProvider owns the persisted light/dark preference and shared night toggle; global CSS supplies both semantic palettes. Why: all screens and overlays share one appearance without hydration flashes.
- TaskInteractions exposes the latest saved specification on demand, keeping questions and approvals inline. Why: avoid repeating plan content under the conversation without hiding consent requests.- Chat @file/@skill/@mcp mentions parse via mentions.ts; agent force-loads mentioned skills, pins up to 6 repo files and notes requested MCP connections. Why: explicit user steering without bloating context.
- Approvals: answers resume in the current chat/plan/build mode (approval-resume.ts); resolved MCP actions leave the chat (Changes tab keeps them) and auto-resume the agent once none remain pending; chat/plan runs load only read-only approval-free MCP tools. Why: consent stays explicit and approvals never strand the agent.
