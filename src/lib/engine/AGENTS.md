# Engine rules
- Run lifecycle (agent_runs) changes only through engine_transition; lifecycle.ts must mirror public.engine_stage_allowed. Why: models and clients cannot set arbitrary states.
- Events append via engine_event with per-run seq allocated atomically; clients replay with an afterSeq cursor. Store milestones only, never tokens or raw tool output. Why: reconnect without duplicates or bloated tables.
- Recorder writes are queued and best-effort; recording failures are counted, never break a run. Why: observability must not cost user work.
- Final stage comes from finalStage() facts (stop, error, blocker, step cap, pending approvals); never COMPLETED just because the model replied.
- Stored errors/events pass redact(); categories come from classifyError. Why: no secrets in logs.
- Model capabilities come from model-registry.ts; unknown models are flagged, not assumed capable. One fallback only, before any tool ran, for provider/rate/timeout/network errors.
- Autonomy is enforced server-side in /api/agent via autonomy.ts; "supervised"/"autonomous" keep legacy meanings. MCP non-read-only actions always need approval at every level.
- Skills: matching/always-on/dependency skills load in full; others are listed and recorded when read_skill loads them.
- Resume: a new run injects a checkpoint built from the previous unfinished run's recorded events (checkpoint.ts); engine_start_run closes the old run. Why: continue without redoing work.
- Memory: rank saved memories locally (memory-rank.ts) and inject the top 40; recall_memory searches the rest. No embeddings. Why: BYOK has no shared embedding key.
- MCP tool lists cache per connection+URL for 6h (mcp-cache.ts); clients open lazily on first call; recheck/failure clears the cache. Resources/prompts are read-only. Why: skip discovery latency safely.
- Discovery: classifyTask (discovery.ts) picks small/medium/large/high_risk; questions go only through ask_user → task_questions, answers only through answer_task_question (atomic, idempotent; only the call closing the last open required question returns resume). Open required questions make finalStage AWAITING_INPUT. Why: no silent guessing, no double resume.
- Suggestions (task_suggestions) are never consent; only an accepted decision changes scope. Specs are versioned rows in task_specifications.
- Reasoning: reasoning.ts maps auto/speed/balanced/deep to provider options only for adapters+models with documented support; unknown models get none. Team size and step caps come from teamPolicy/profilePolicy; dispatch is forced only for large/high-risk non-speed work. Roles route to coding/reviewer models when configured, else the master. Why: truthful capabilities, smallest effective team.
- Repo trees cache across runs per user+repo+branch keyed by head SHA (tree-cache.ts, 30 min, 50 entries). Helpers end with a fenced JSON report validated by worker-report.ts; missing reports or unowned files are surfaced to the master as contractIssues. Skill auto-matching uses measured completion rates (skill-stats.ts, ≥4 samples) only for weak keyword matches; triggers/names/always-on are unaffected.
