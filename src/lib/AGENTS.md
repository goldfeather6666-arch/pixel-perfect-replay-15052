# Library rules
- team-models resolves role model+credential together; team-models.server validates owner/provider/endpoint before decrypting and never exposes keys. Why: parallel role models cannot accidentally use the lead API key.
- free-skills.ts owns the free-only contract, original domain catalogue and conservative text/license eligibility; importer resolves nearest license at immutable commit and blocks unresolved script/service audits. Registry revisions capture edits and disabled rollback. Why: no directory listing or public repository implies safe/free execution.
- project-setup uses service-only encrypted secret requests and domain approvals bound to owner/task/account/project; DNS+ownership precede custom APP_URL/auth sync, secure submission authorizes target-specific env writes but never deployment. Provider-only callbacks remain explicit blockers without access. Why: durable consent and no credential exposure.
- deployment-env.ts emits Vite/browser and server database names without Next public aliases; customer-auth.server verifies narrow signup/site patches during authorized task sync, while Vercel production domains define the final public URL; privileged keys stay server-only. Missing-env repairs verify pinned links and Connect & sync before manual values, then rebuild/probe. Guided setup stores encrypted owner tokens/service-only DB settings, syncs Vercel targets, commits blank env templates and ordered task-tracked migrations SQL. Why: secure portable setup.
- Read engine/AGENTS.md before engine edits. Why: scoped run and ownership contracts.
- vercel-build-review extracts redacted warnings from successful and failed build logs; agents must review each current-commit finding and reverify fixes through the existing quality gate. Why: READY alone can conceal actionable issues.
- Global RPC fetch inspects stale-manifest failures before deserialization and performs bounded document recovery without replaying requests; approval polls keep errors visible and never throw into page rendering. Why: restart recovery without duplicated external actions or blank chat.
- Prompt refinement verifies owner-scoped task and credential rows, uses that task’s BYOK model, streams with cancellation and never executes tools or saves drafts. Why: isolated billing, ownership and consent.
