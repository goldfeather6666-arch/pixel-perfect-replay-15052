# Library rules
- team-models resolves role model+credential together; team-models.server validates owner/provider/endpoint before decrypting and never exposes keys. Why: parallel role models cannot accidentally use the lead API key.
- free-skills.ts owns the free-only contract, original domain catalogue and conservative text/license eligibility; importer resolves nearest license at immutable commit and blocks unresolved script/service audits. Registry revisions capture edits and disabled rollback. Why: no directory listing or public repository implies safe/free execution.
- project-setup uses service-only encrypted secret requests and domain approvals bound to owner/task/account/project; DNS+ownership precede custom APP_URL/auth sync, secure submission authorizes target-specific env writes but never deployment. Provider-only callbacks remain explicit blockers without access. Why: durable consent and no credential exposure.
- deployment-env.ts emits Vite/browser and server database names without Next public aliases; customer-auth.server verifies narrow signup/site patches during authorized task sync, while Vercel production domains define the final public URL; privileged keys stay server-only. Missing-env repairs verify pinned links and Connect & sync before manual values, then rebuild/probe. Guided setup stores encrypted owner tokens/service-only DB settings, syncs Vercel targets, commits blank env templates and ordered task-tracked migrations SQL. Why: secure portable setup.
- Read engine/AGENTS.md before engine edits. Why: scoped run and ownership contracts.
- vercel-build-review extracts redacted warnings from successful and failed build logs; agents must review each current-commit finding and reverify fixes through the existing quality gate. Why: READY alone can conceal actionable issues.
- Global RPC fetch inspects stale-manifest failures before deserialization and performs bounded document recovery without replaying requests or aborting a document still arriving, with a capped number of consecutive reloads; approval polls keep errors visible and never throw into page rendering. Why: restart recovery without duplicated external actions, blank screens or reload storms.
- Prompt refinement verifies owner-scoped task and credential rows, uses that task’s BYOK model, streams with cancellation and never executes tools or saves drafts. Why: isolated billing, ownership and consent.- Workspaces: owner server → shared server (FORGE_SHARED_RUNNER_OWNER) → pooled E2B accounts (e2b-pool.ts, round-robin, 15-min cooldown on quota errors; connect/kill try every key). Why: free compute spread across accounts without task failure.
- model-pricing.ts owns every model cost label; providers.server.ts supplies only provider-reported prices and a free label needs a zero/absent price, a :free id or a reachable self-hosted URL, never a name guess. Why: free/cost claims stay truthful across providers.
- Task database: resolveTaskDatabaseRef auto-links the saved, repo-inherited or sole account project; agents fix missing preview DB via list_databases/link_database. Why: previews never silently lack a database.
- Task env: preview-manager writePublicEnv/seedTaskEnv is the only writer of sandbox env (/tmp/forge-task.env + git-excluded repo .env.local); syncTaskDatabase pushes DB vars, production APP_URL and saved project secrets to Vercel. Why: one source so preview, agent shell and Vercel never drift.
- Prompt audit: every agent file write records the driving prompt in change_provenance; fileHistory/provenanceChain build the "why did this change" drill-down and count a change verified only when a passing qa.gate exists for that run. Why: trust and training without guessing intent.
- Model comparison: model-stats aggregates only the owner's own agent_runs; a cancelled, awaiting or open run never counts as a failure, and a model with no decisive outcome shows no success rate. Why: honest per-model quality and cost.
- Performance budget-as-code: perf-budget parses a committed budget.json, measures the real build output, blocks the QA gate on a breach with the fix suggestion, and reports unmeasured metrics as unmeasured. Why: budgets enforced, never silently passed.
- Authorship tags compare current Git blob SHA with content-addressed change provenance; missing historical evidence stays unknown. Why: later human edits must never be mislabeled as agent output.
- Maintenance uses opt-in owner-scoped read-only bounded GitHub inspection, never shell/model calls or repo writes; fixes enter live chat for normal approval. Why: idle suggestions cannot create hidden external effects.
